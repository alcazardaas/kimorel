# Security policy

Kimorel is pre-release; only the current development line receives fixes. No hosted service, authentication or private user data is required.

Do not post exploit details, credentials or private recordings in public issues. Once the repository is hosted, use its GitHub **Security → Report a vulnerability** feature for private disclosure. If private reporting is not enabled, request a private contact from the maintainers without publishing the exploit. No verified security email address is configured yet.

Include affected revision/package versions, reproduction steps, impact and a suggested mitigation. Asset parsing is an untrusted-input boundary: maintainers should review files and dependencies before running import tools. Do not execute scripts embedded in submissions. Clinical concerns and unsafe exercise instructions also require human review; this project does not provide medical advice.
